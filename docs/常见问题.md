# 常见问题

---

## 安装与启动

<details>
<summary><b>双击 .cmd 没反应 / 闪一下就没了</b></summary>

通常是 PowerShell 执行策略拦下了。打开 PowerShell，`cd` 到解压目录后手动运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\MigrateGui.ps1
```

这样能看到具体报错。仍然不行请带上报错信息提 [Issue](https://github.com/wang1413520/Cpan_cleaner/issues)。

</details>

<details>
<summary><b>需要安装什么依赖吗？</b></summary>

**什么都不用装。** 纯 PowerShell 5.1 + WinForms，Windows 10/11 自带。
不装模块、不装包、不联网也能跑（只有 AI 标注需要联网，而那是可选的）。

</details>

<details>
<summary><b>需要管理员权限吗？</b></summary>

**不需要。**

NTFS 上创建 Junction 只需对目标位置的写权限——只有**符号链接**（`/D`）才需要管理员或开发者模式。

界面启动时会**实测**这个能力（真的建一个 Junction 再删掉），而不是靠猜"是不是管理员"。

只有当源或目标位于受保护位置（如 `Program Files`）时才需要提权。

</details>

<details>
<summary><b>Linux / macOS 能用吗？</b></summary>

不能。本工具依赖 Windows 特有的 robocopy、`mklink`、NTFS Junction 和 DPAPI。
Linux 上类似需求可以直接用 `mv` + `ln -s`。

</details>

## 扫描

<details>
<summary><b>扫描要多久？</b></summary>

遍历整块盘，通常 **1–3 分钟**。磁盘越大、文件越多越慢。

扫描是**纯只读**的，不会修改任何东西。可以随时关掉窗口。

</details>

<details>
<summary><b>为什么有些目录没出现在清单里？</b></summary>

三个可能：

1. **体积没到阈值** —— 调小「最小体积 (MB)」
2. **不在扫描范围内** —— 工具只扫盘根 + 用户目录 + `AppData` + `Program Files` + `ProgramData`
3. **是容器目录** —— `C:\Users`、`C:\ProgramData` 这类是"容器"，本身不列为候选，其子目录才单独评估

</details>

<details>
<summary><b>扫描结果和资源管理器显示的体积不一致？</b></summary>

统计时**排除了重解析点**（Junction/符号链接），所以数字会小于资源管理器。

这是刻意的——跟进链接会重复统计（同一个目录被算两次）。

</details>

<details>
<summary><b>「已迁」的目录显示 `—` 而不是体积？</b></summary>

因为那是链接，工具不跟进遍历。链接目标在说明栏显示，体积在目标盘，不重复计入。

</details>

## 判定与分类

<details>
<summary><b>`DELETE`（可删）到底该删还是该迁？</b></summary>

**该删，不该迁。**

把缓存搬到 D 盘，垃圾只是换个盘躺着——C 盘少了 2 GB，D 盘多了 2 GB，**你一点空间都没省**。

而且这类目录程序通常会自己重建，Junction 可能被顶掉。

用法：第 3 页筛选「可删 DELETE」→ 全选 → 点「清理勾选项」。

</details>

<details>
<summary><b>`REDIRECT`（重定向）是什么意思？</b></summary>

桌面 / 文档 / 下载这类**用户文件夹**。它们不该用 Junction，应该用 Windows 自带的：

右键文件夹 → **属性 → 位置 → 移动**

这是官方支持的方式，比 Junction 更稳，Windows 会同步更新注册表里的路径。

</details>

<details>
<summary><b>为什么 `OneDrive` 被判成禁区？</b></summary>

因为它的重解析标记是**云文件占位符**（`0x9000701a`），不是链接。

它既没被迁移，也不该被当作"已处理"。而且云同步目录用 Junction 重定向可能导致同步异常。

</details>

<details>
<summary><b>`Program Files` 里的程序能迁吗？</b></summary>

**默认不能**（软禁区）。

命令行可以加 `-Force -ForceReason "理由"` 强制放行，但**界面有意不提供这个入口**。

原因：这类程序常依赖注册表绝对路径、Windows 服务、更新机制，迁移后可能损坏。
更稳的做法是用程序自己的设置改数据/缓存位置。

</details>

<details>
<summary><b>`C:\Windows` 能迁吗？</b></summary>

不能。硬禁区，`-Force` 也解不开。

</details>

## 迁移

<details>
<summary><b>预检报「文件被占用」怎么办？</b></summary>

**完全退出对应程序**，包括：

- 系统托盘图标（右键退出，不是点 × 关窗口）
- 后台服务
- 用任务管理器确认没有残留进程

这是**保护机制**，不是 bug——数据库文件被占用时强行复制会损坏数据。

</details>

<details>
<summary><b>预检报「检测到 SQLite 活动标记」？</b></summary>

说明目录里有 `*.sqlite-wal` 或 `*.sqlite-shm` 文件，通常意味着程序正在运行。

先完全退出程序再试。如果确实没开，可能是上次异常退出留下的残留——再次启动程序让它正常关闭一次，或者确认没有正在运行的进程后继续。

</details>

<details>
<summary><b>预检报「源已经是链接」？</b></summary>

这个目录**已经迁移过了**，不需要重复迁移。

用「刷新状态」（F5）刷新一下清单，它会归入「已迁 ALREADY」。

</details>

<details>
<summary><b>7 项里有 2 项预检失败，剩下的会迁移吗？</b></summary>

**会。** 预检是逐项独立的，失败项只跳过它自己，队列继续处理其余项。

```
[1/7]  项目1  [成功]
[2/7]  项目2  [成功]
[3/7]  项目3  => 预检未通过，跳过本项（未做任何写操作）
[4/7]  项目4  [成功]
...
队列结束：成功 5 / 失败 0 / 跳过 2 / 共 7
```

失败的项**一个字节都没动**，还是普通目录，程序照常能跑。

</details>

<details>
<summary><b>重复执行会不会出问题？</b></summary>

**不会，是幂等的。**

已迁移的项会被预检的「源已经是链接，不能套娃」拦下，**不会重复搬迁、不会套娃**。

所以处理完失败项后，可以直接把整份清单再跑一遍。

</details>

<details>
<summary><b>迁移过程中关掉窗口会怎样？</b></summary>

会**中止**当前正在执行的那一项，子进程会被一并终止。

- 已完成的项：保留，不受影响
- 正在执行的项：源目录完好（复制阶段不碰源），目标可能有残留
- 未开始的项：不会执行

重新打开后「回滚上次执行」仍可用（记录持久化在 `report\migration\`）。

</details>

<details>
<summary><b>迁移后程序打不开怎么办？</b></summary>

点「**回滚上次执行**」。

工具会自动判断当前磁盘状态并选**代价最低**的方案：

- 如果只是链接丢了（方案 B），**25 毫秒**就能修好，零数据移动
- 如果链接已生效需要撤销（方案 C），会把数据完整搬回

</details>

<details>
<summary><b>迁移失败了，目标盘上留了一份副本怎么办？</b></summary>

这是「复制成功但卡在重命名/建链接」留下的**孤儿副本**。源目录完好，但目标盘白占了一份等量的空间。

工具能识别并清理（**方案 D**）：

```powershell
Import-Module .\MigrateCore.psm1 -Force

# 先只看它怎么判断（不删任何东西）
Undo-DirectoryMigration -ManifestPath .\report\migration\migrate-XXX-时间戳.json

# 确认后清理
Undo-DirectoryMigration -ManifestPath .\report\migration\migrate-XXX-时间戳.json -CleanOrphanTarget
```

删除前会与 manifest 记录比对文件数与字节数，**不符就拒绝删除**。

</details>

## 清理

<details>
<summary><b>清理会不会把不该删的删掉？</b></summary>

有四层保护：

1. **只对判定为 `DELETE` 的项生效** —— 可迁/待定/禁区一律不允许
2. **强制预览** —— 完整列出路径与体积，勾「我已确认」才可执行
3. **执行器独立再过滤** —— 不信任界面传来的内容，自己再挡一遍
4. **硬禁区 + 链接安全** —— 盘符根/Windows/Program Files/ProgramData/用户主目录/回收站一律拒绝；遇 Junction 只删链接本身

默认还是「**移入回收站**」模式，删错了能捞回来。

</details>

<details>
<summary><b>「移入回收站」和「永久删除」有什么区别？</b></summary>

| | 移入回收站（默认） | 永久删除 |
|---|---|---|
| 可恢复 | ✅ 能 | ❌ 不能 |
| 立即释放空间 | ❌ 要再清空回收站 | ✅ 立即 |
| 适用 | 第一次清理，不确定的东西 | 确认无用 |

建议先用「移入回收站」，确认没问题、清空回收站后，以后再用「永久删除」。

</details>

<details>
<summary><b>为什么回收站不能清理？</b></summary>

`C:\$Recycle.Bin` 是 Windows 管理的特殊目录，工具会**自动排除**它。

请用系统方式：

- 双击桌面「回收站」→ 左上角「清空回收站」
- 或：右键回收站 → 属性 → 选 `(C:)` → 「自定义大小」→ 填 `2048` MB

**后者更稳**：之后 C 盘回收站最多占 2 GB，超了自动清理最旧的。

</details>

<details>
<summary><b>清空回收站能恢复吗？</b></summary>

**不能。** 这是 Windows 里唯一不可逆的删除操作。

所以本工具**不碰**回收站——把它留给你自己决定。

如果拿不准，先用「限制容量」的方式（让超出的自动滚动淘汰），而不是一次性全清。

</details>

## AI 标注

<details>
<summary><b>不配 AI 能用吗？</b></summary>

**完全能。** AI 标注是可选的。

规则引擎本身已经给出完整的六类判定。AI 只是把 `REVIEW`（待定）那部分陌生目录名翻译成人话，
让你更敢下决定。

</details>

<details>
<summary><b>API 端点填什么？</b></summary>

必须填**服务商的接口地址**（通常以 `/v1` 结尾）。工具会自动拼 `/chat/completions`。

| 服务商 | 端点 |
|---|---|
| DeepSeek | `https://api.deepseek.com/v1` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 月之暗面 | `https://api.moonshot.cn/v1` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| 硅基流动 | `https://api.siliconflow.cn/v1` |
| OpenAI | `https://api.openai.com/v1` |
| 本地 Ollama | `http://localhost:11434/v1` |

</details>

<details>
<summary><b>怎么知道模型名对不对？</b></summary>

点「**测试连接**」。它会发一条最小请求并显示结果：

- ✅ `连接成功` —— 端点/模型/Key 都可用
- ❌ `HTTP 404 ... model_not_found` —— 该服务商没有这个模型
- ❌ `HTTP 401 ... Invalid token` —— Key 不对或过期

失败时会**原样显示服务商返回的错误信息**，一看就知道问题在哪。

</details>

<details>
<summary><b>API Key 存在哪？安全吗？</b></summary>

存在工具目录下的 `ai-config.json`，**用 Windows DPAPI 加密**。

DPAPI 是**当前用户作用域**——只有同一台机器上的同一个 Windows 账户能解开。
配置文件被拷到别的机器、或被同步到网盘，都解不出你的 key。

端点与模型是明文保存的（它们不是秘密）。想清掉 key 点「**清除已保存的密钥**」。

> 换 Windows 账户后 key 会解密失败，界面会提示重新输入，不会崩。

</details>

<details>
<summary><b>会把我的文件内容传出去吗？</b></summary>

**不会。**

发给 API 的是**脱敏元数据**：路径（用户名替换为 `__USER__`）、体积、文件数、扩展名分布、是否被占用。

**绝不含任何文件内容。**

想核实的话，先点「**预览(不花钱)**」——它不联网、不产生费用，只把要发出去的内容原样打印出来。

</details>

<details>
<summary><b>「是什么 (AI)」这栏出现乱码？</b></summary>

这是 PowerShell 5.1 的一个已知坑：`Invoke-RestMethod` 在服务端 `Content-Type` 不带
`charset=utf-8` 时，会按 ISO-8859-1 解码响应体，中文全变成 `åæ¶ç«` 这种 mojibake。

**已在 v1.0.0 修复**（改为自行取原始字节按 UTF-8 解码）。

如果已经有被写坏的标注结果，不用重新调用 API，跑这个工具还原：

```powershell
powershell -ExecutionPolicy Bypass -File .\Repair-Annotation-Encoding.ps1
```

乱码是**可逆的**（Latin-1 编回字节 → UTF-8 解码），能完整还原。

</details>

<details>
<summary><b>AI 会不会误判，把该保留的判成可删？</b></summary>

**不会造成损失**，因为 **AI 只有否决权，没有批准权**：

- 规则判 `BLOCK` 的目录**绝不发给 AI**
- AI **不能把任何判定升级**为更激进的操作
- AI 只能**降级**（例如把 `DELETE` 拉回 `REVIEW`，意思是"建议别删"）
- AI 的建议若比规则更激进，**直接忽略**，只作展示

结果表里被 AI 拉回的项会标 `[AI 否决]`，并写进 `report\ai-veto.txt`。

</details>
