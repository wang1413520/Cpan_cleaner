# 使用教程

从零开始，一步步把 C 盘的目录搬到 D 盘。

> 全程**不需要管理员权限**，但**迁移时请关闭相关程序**。

## 第 0 步：下载与解压

### 下载

**[点此下载 ZIP](https://github.com/wang1413520/Cpan_cleaner/archive/refs/heads/main.zip)**

或用 git：

```bash
git clone https://github.com/wang1413520/Cpan_cleaner.git
```

### 解压到哪

建议放在 **D 盘**，例如 `D:\Cpan_cleaner`。

> 不要放在 `C:\Program Files` 下面——那样工具自己的运行产物也会占 C 盘。

### 启动

双击 **`启动-C盘迁移助手.cmd`**。

正常的话会出现一个窗口，标题是 `C 盘迁移助手 — 扫描 / AI 标注 / 决策清单`，
里面有四个页签：

```
1. 扫描  |  2. AI 标注  |  3. 决策清单  |  4. 执行迁移
```

> **双击没反应？** 可能是 PowerShell 执行策略被拦。
> 打开 PowerShell，`cd` 到解压目录，运行：
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\MigrateGui.ps1
> ```
> 还不行的话，把报错信息发到 [Issues](https://github.com/wang1413520/Cpan_cleaner/issues)。

## 第 1 步：扫描 C 盘

切到「**1. 扫描**」页：

| 字段 | 填什么 |
|---|---|
| 扫描盘符 | `C:\` |
| 最小体积 (MB) | `100`（可调，填小了会列出很多无关目录） |
| 报告目录 | 默认即可 |

点「**开始扫描**」。**大约 1–3 分钟**（要遍历整块盘），进度会实时显示在下方日志框。

扫描完成后会**自动跳到「3. 决策清单」**并载入结果。

> 扫描是**纯只读**的，不会修改任何东西。

---

## 第 2 步：看懂扫描结果

「3. 决策清单」会列出所有超过阈值的目录，每行有颜色区分：

| 颜色 | 判定 | 含义 | 你该做什么 |
|---|---|---|---|
| 🟢 绿 | `ALREADY` **已迁** | 已经是链接 | 不用管 |
| 🔴 红 | `DELETE` **可删** | 缓存/临时/日志/安装包残留 | **清理**，不要迁移 |
| 🔵 蓝 | `MIGRATE` **可迁** | 应用数据目录 | 用本工具**迁移** |
| 🟠 橙 | `REDIRECT` **重定向** | 桌面/文档/下载 | 用系统功能，**别用本工具** |
| ⚪ 灰 | `REVIEW` **待定** | 规则判断不了 | 看 AI 标注，或自己判断 |
| ⚫ 深灰 | `BLOCK` **禁区** | 系统目录/驱动/云同步 | **绝对不碰** |

顶部有筛选下拉框，可以只看某一类。

> **重要观念**：`DELETE` 是**该删掉**，不是**该搬走**。
> 把缓存搬到 D 盘，垃圾只是换个盘躺着，你一点空间都没省出来。

## 第 3 步：AI 标注（可选）

**这一步可以跳过。** 不配 AI 的话，前两步照样能走完。

想配的话，切到「**2. AI 标注**」页：

| 字段 | 示例 |
|---|---|
| API 端点 | `https://api.deepseek.com/v1` |
| 模型 | `deepseek-chat` |
| API Key | 你自己服务商的 key |

> **设置会自动保存**，下次打开自动填入，不用重复输。
> API Key 用 **Windows DPAPI 加密**存储——只有你这台机器的这个 Windows 账户能解开。

### 先测试再花钱

点「**测试连接**」。它会发一条最小请求，告诉你端点/模型/Key 是否都可用：

```
连接成功
  端点  https://api.deepseek.com/v1
  模型  deepseek-chat
  延迟  412 ms
  返回  {"ok":true,"msg":"连接正常"}
```

失败的话会显示服务商返回的原始错误，例如：

```
连接失败（6 ms）
HTTP 404
{"error":{"message":"模型 xxx 不存在","code":"model_not_found"}}
```

### 正式标注

1. 点「**预览(不花钱)**」——**不联网、不产生费用**，只把要发出去的内容原样打印给你看
2. 确认没暴露你不想外发的东西（默认已把用户名替换成 `__USER__`）
3. 点「**开始标注**」

标注结果会填进「3. 决策清单」的「是什么 (AI)」列。

> **不想用云端？** 装 [Ollama](https://ollama.com/)，端点填 `http://localhost:11434/v1`，
> 模型填你本地拉的名字，完全不出本机。

## 第 4 步：清理可删项

在「3. 决策清单」：

1. 筛选选「**可删 DELETE**」
2. 点「**全选可删**」
3. 点「**清理勾选项**」（顶栏最右侧，红字）

会弹出确认框：

```
将处理以下 12 项，合计 47.40 GB：

  体积GB     绝对路径
  19.36      C:\$Recycle.Bin
  11.11      C:\Users\你\AppData\Local\Temp
   6.78      C:\Users\你\AppData\Local\pip
   ...

以下 1 项不符合清理条件，已自动排除：
  C:\$Recycle.Bin   ——   受保护：回收站（请用系统的「清空回收站」）

  ● 移入回收站（可恢复，推荐）
  ○ 永久删除（不可恢复）
  ☐ 我已确认以上内容无误

              [ 执行清理 ]  [ 取消 ]
```

**选择「移入回收站」**（默认）——这样万一删错了还能捞回来。

> 移入回收站**不会立即释放磁盘空间**，需要再清空回收站才会真正腾出空间。
> 但至少给了你反悔的机会。

### 关于回收站本身

`C:\$Recycle.Bin` 会被**自动排除**——它是 Windows 管理的特殊目录。
想清它请用系统方式：

- **方式 A**：双击桌面「回收站」→ 左上角「清空回收站」
- **方式 B**：右键回收站 → 属性 → 选 `(C:)` → 「自定义大小」→ 填 `2048` MB → 确定

> **方式 B 更稳**：之后 C 盘回收站最多占 2 GB，超了自动清理最旧的，
> 你不用再做"要不要全清"的一次性决定。

## 第 5 步：迁移可迁项

### 5.1 准备目标目录

先去 D 盘建好父目录，比如 `D:\moved`。

> 最终路径 = **父目录 \ 源文件夹名**
> 例如源是 `C:\Users\你\AppData\Local\JetBrains`，父目录填 `D:\moved`，
> 最终会落在 `D:\moved\JetBrains`。

### 5.2 关闭相关程序 ⚠️

**这步最关键。** 迁移时要重命名源目录，而被程序打开的文件会锁住目录，导致失败。

- 关掉对应的软件，**包括系统托盘图标**
- 用任务管理器确认没有残留进程

> 工具会在预检阶段检测文件占用，被占用就拒绝执行——这是保护机制，不是 bug。

### 5.3 载入与预检

切到「**4. 执行迁移**」页：

1. 「目标盘父目录」填 `D:\moved`
2. 点「**① 载入勾选项**」—— 把第 3 页勾选的项载入队列
3. 点「**② 仅预检**」—— **纯只读，不做任何写操作**

预检日志会逐条列出 13 项检查：

```
  [OK  ] Junction 能力 — 可在该卷创建目录联接（NTFS 上不需要管理员）
  [WARN] 管理员身份 — 当前非管理员：迁移用户目录无影响
  [OK  ] 源目录 — 存在，4.35 GB / 30623 个文件
  [OK  ] 源类型 — 普通目录
  [OK  ] 黑名单 — 不在任何禁区
  [OK  ] 卷 — C:\ -> D:\
  [OK  ] 目标占用 — 目标可用：D:\moved\JetBrains
  [OK  ] 目标父目录 — 存在：D:\moved
  [OK  ] 可用空间 — 需要 5.00 GB（含 15% 余量），可用 148.00 GB
  [OK  ] 内含链接 — 无重解析点
  [OK  ] 运行中程序 — 未发现 SQLite 活动标记
  [FAIL] 文件占用 — 有 19 个文件正被占用，请先退出相关程序：
          C:\Users\你\AppData\Local\JetBrains\...\xxx.log
  [OK  ] 源可写 — 源父目录可写
  [OK  ] 目标可写 — 目标目录可写
```

有 `[FAIL]` 就照它说的处理，然后重新预检。

### 5.4 执行

预检全绿后，点「**③ 开始执行**」，会弹二次确认。

执行过程中：
- 进度条按项推进
- 状态行显示 `[3/12] 复制 — JetBrains   成功 2 / 失败 0`
- 下方日志实时流式输出

**预检不通过的项会被自动跳过**，其余照常迁移——不会因为一项失败就中断整个队列。

### 5.5 验证

迁移完成后，建议手动确认一下：

```cmd
dir /AL "C:\Users\你\AppData\Local"
```

看到这样的行就对了：

```
<JUNCTION>     JetBrains [D:\moved\JetBrains]
```

再打开对应的程序，能正常用就说明成功了。

> 还可以按 **F5** 或点「刷新状态」——已迁移的项会自动归入「已迁 ALREADY」，
> 体积显示为 `—`，说明栏写「已迁移，现在是指向 X 的链接」。

## 第 6 步：重定向用户文件夹

`桌面` / `文档` / `下载` 这三类，扫描结果标的是 `REDIRECT`（橙色），
**不要用本工具迁移**，要用 Windows 自带的功能：

1. 打开文件资源管理器，右键「桌面」（或文档）
2. 属性 → **位置** 标签页
3. 点「移动…」→ 选 `D:\Desktop` 这类目标
4. 确定 → 提示是否移动文件 → 选「是」

> 这是官方支持的方式，比 Junction 更稳，而且 Windows 会同步更新注册表里的路径。
>
> `下载` 文件夹在部分 Windows 11 版本里没有「位置」标签页，可以用注册表
> `Shell Folders` 修改，或者干脆定期手动清空。

## 第 7 步：出问题怎么回滚

### 情况 1：界面上迁移失败了

「4. 执行迁移」的结果表会显示红色的「失败」，日志里有原因。
点「**回滚上次执行**」即可。

### 情况 2：迁移成功但程序打不开

同样点「回滚上次执行」。

### 情况 3：换了台机器 / 关了界面

迁移记录是**持久化**的，在 `report\migration\` 下：

```
migrate-JetBrains-20260912-103045.json    ← 这是回滚凭据，别删
migrate-JetBrains-20260912-103045.robocopy.log
```

用命令行回滚：

```powershell
cd D:\Cpan_cleaner
Import-Module .\MigrateCore.psm1 -Force

# 自动判断当前状态并选最低代价的方案
Undo-DirectoryMigration -ManifestPath .\report\migration\migrate-JetBrains-20260912-103045.json
```

### 回滚的四种方案

工具会**自动选代价最低的**：

| 方案 | 场景 | 耗时 | 数据移动 |
|---|---|---|---|
| **A 重命名回滚** | 原位置有 `.__migrating_*` 残留 | **毫秒级** | **0 字节** |
| **B 补建链接** | 目标完整、原位置缺链接 | **毫秒级** | **0 字节** |
| **C 完整搬回** | 链接已生效、就是要撤销 | 秒级 | 全部 |
| **D 清理孤儿** | 源完好、目标留有失败时的副本 | 秒级 | 0 字节（删副本） |

> **方案 A / B 是零数据移动的**——因为它们只需要改个名字或建个链接。
> 这就是「用重命名代替删除」这个设计带来的好处。

### 手动恢复（最坏情况）

如果工具也帮不上忙，手工操作：

```cmd
:: 1) 删除链接 —— 必须用 rmdir，不能加 /S
rmdir "C:\Users\你\AppData\Local\JetBrains"

:: 2) 把数据搬回去
robocopy "D:\moved\JetBrains" "C:\Users\你\AppData\Local\JetBrains" /E /MOVE

:: 3) 确认无误后清理目标残留
rmdir "D:\moved\JetBrains"
```

> ⚠️ **绝对不要**用 `rd /s` 或 `Remove-Item -Recurse` 删除 Junction——
> 那会**顺着链接把 D 盘的真实数据一起删掉**。

## 完整实战示例

假设你要迁移 JetBrains 的 IDE 缓存（约 4.35 GB）：

```
① 双击 启动-C盘迁移助手.cmd
② 「1. 扫描」→ 盘符 C:\ → 最小体积 100 → 开始扫描 → 等待 2 分钟
③ 「3. 决策清单」→ 筛选「可迁 MIGRATE」→ 找到 C:\Users\你\AppData\Local\JetBrains
④ 在 D 盘建好 D:\moved 目录
⑤ 完全退出所有 JetBrains IDE（含托盘）
⑥ 「3. 决策清单」勾选 JetBrains 那一行 → 点「导出清单」留个记录
⑦ 「4. 执行迁移」→ 目标盘父目录填 D:\moved → 点「① 载入勾选项」
⑧ 点「② 仅预检」→ 检查是否有 [FAIL]
⑨ 全绿 → 点「③ 开始执行」→ 二次确认
⑩ 看到「结束：成功 1 / 失败 0 / 跳过 0 / 共 1」
⑪ 重开 IDE 确认正常
⑫ 按 F5 刷新，「3. 决策清单」里 JetBrains 变成「已迁 ALREADY」
```

## 检查清单

迁移前逐条确认：

- [ ] **目标盘有足够空间**（源体积 × 1.15 以上）
- [ ] **目标父目录已建好**
- [ ] **相关程序已完全退出**（含托盘图标）
- [ ] **已点「仅预检」且无 `[FAIL]`**
- [ ] **该目录不是** `Windows` / `Program Files` / `ProgramData` / 回收站
- [ ] **该目录没有** 正在运行的数据库（`.sqlite-wal` 存在说明程序还在跑）
- [ ] **重要数据已备份**（虽然工具设计上很安全，但备份永远是对的）

迁移后验证：

- [ ] `dir /AL` 能看到 `<JUNCTION>`
- [ ] 对应程序能正常打开
- [ ] 目标盘上确实有了数据
- [ ] C 盘空间确实释放了

出问题：

- [ ] 别慌 —— **源目录在任何失败情况下都是完好的**
- [ ] 点「回滚上次执行」
- [ ] 实在不行按上面的「手动恢复」操作
