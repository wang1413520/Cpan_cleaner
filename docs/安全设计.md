# 安全设计

本文说明本工具为什么"敢动你的数据"。

所有设计围绕一个目标：**任何失败都不会破坏源目录。**

---

## 一、执行顺序：把风险窗口压到最小

```
预检 ──► 复制 ──► 校验 ──► 重命名 ──► 建链接 ──► 验证 ──► 删残留
 │        │        │         │          │         │        │
 不改任何  源不动   不一致就   毫秒级     失败可    读一个   失败也
 东西             不删源               秒回      文件     无所谓
```

### 为什么这样排序

**① 复制阶段绝不碰源目录**

如果先删源再复制（robocopy `/MOVE` 的跨卷行为），中途断电/进程被杀会留下
「源删了一半、目标不完整」的状态——**那才是真正会丢数据的场景**。

本工具先完整复制。此阶段任何失败：

```
源目录   ✅ 完好
目标     ⚠️ 可能不完整（删掉重来即可）
程序     ✅ 照常运行
数据损失 0
```

等于什么都没发生。

**② 校验通过前绝不删源**

逐文件比对**数量**与**总字节数**，差一个字节就停下，且保留源与已复制的目标，
提示用户手动核对。

**③ 用「重命名」代替「删除」做切换**

`Remove-Item -Recurse` 是耗时操作——GB 级要几十秒。如果先删源再建链接，
这期间源已经消失、链接还没建立，**程序在这个窗口里打不开**。

改成 `Rename-Item`（元数据操作，毫秒级）后，这个窗口从几十秒压缩到接近 0：

```
旧:  删除源（30 秒）──────────►  建链接    ← 30 秒的"程序打不开"窗口
新:  重命名源（1 毫秒）►  建链接          ← 窗口≈0
```

**④ 删残留前先摘掉里面的重解析点**

如果源目录内部还有 Junction，直接 `Remove-Item -Recurse` 可能**顺着链接
把目标盘的真实数据一起删掉**。本工具先对每个重解析点执行 `rmdir`（不带 `/S`，
只删链接本身），再整体删除。

## 二、四层回滚

| 方案 | 触发条件 | 动作 | 数据移动 |
|---|---|---|---|
| **A 重命名回滚** | 原位置有 `.__migrating_*` 残留 | 改回原名 | **0** |
| **B 补建链接** | 目标完整、原位置缺链接 | `mklink /J` | **0** |
| **C 完整搬回** | 链接已生效，用户要撤销 | `robocopy /MOVE` | 全部 |
| **D 清理孤儿** | 源完好、目标留有失败时的副本 | 删除目标副本 | 0（删副本） |

工具会**自动判断当前磁盘状态**并选代价最低的方案，也可用 `-Method A|B|C|D` 强制指定。

### 实测耗时

```
方案 A  6 ms    移动 0 字节
方案 B  25 ms   移动 0 字节
```

**核心原则：只要源目录没被真正删除，就永远不需要「搬回来」这种高成本回滚。**

### 方案 D 的安全校验

删除孤儿副本前，会比对目标当前的文件数与字节数是否与 manifest 记录一致：

```
拒绝清理：目标文件数与 manifest 记录不符
  manifest 记录 10 个，实际 7 个
  目标 D:\moved\X 可能不是本工具复制的副本，请人工确认后再处理
```

不一致就**拒绝删除**——宁可留着占空间，也不误删未知数据。

## 三、13 项预检

任意一项 `FAIL` → **跳过该项，不做任何写操作**，且**不中断队列**。

| 检查点 | 可能结果 | 说明 |
|---|---|---|
| Junction 能力 | OK / **FAIL** | 实测能否在该卷创建目录联接（不是靠猜"是否管理员"） |
| 管理员身份 | OK / WARN | 仅提示。NTFS 上创建 Junction 本就不需要管理员 |
| 源目录 | **FAIL** / OK | 不存在或不是目录 |
| 源类型 | **FAIL** / OK | 已经是链接 → 拒绝套娃；是云同步占位符 → 拒绝 |
| 黑名单 | **FAIL** / WARN / OK | 硬禁区一律拒绝；`Program Files` 子目录需 `-Force` |
| 卷 | **FAIL** / OK | 同卷不需要本工具，直接用 `Move-Item` |
| 目标占用 | **FAIL** / OK | 目标已存在 → 绝不覆盖 |
| 目标父目录 | **FAIL** / OK | 不存在或目标盘不可用 |
| 可用空间 | **FAIL** / OK | 需要源体积 × 1.15 |
| 内含链接 | OK / WARN | 列出源目录内的重解析点，说明迁移后会怎样 |
| 运行中程序 | WARN / OK | 检出 SQLite `-wal`/`-shm`，提示先退出程序 |
| 文件占用 | **FAIL** / OK | 逐个文件尝试独占打开，列出前 20 个被占用的 |
| 源可写 / 目标可写 | **FAIL** / OK | 实际创建并删除探针文件验证 |

### 关于「文件占用」检查的局限

它是**快照**，不是保证。程序可能在校验通过之后、重命名之前又打开了文件。

所以重命名环节还有**退避重试 5 次**；仍然失败则给出明确提示
（"请完全退出相关程序"），而不是干巴巴的"访问被拒绝"。

此时状态是：**源目录完好 + 目标已有一份完整副本**（方案 D 可清理）。

## 四、黑名单

### 硬禁区（任何情况都拒绝，`-Force` 也解不开）

```
C:\                    驱动器根目录
C:\Windows\            系统目录
C:\Program Files\      程序安装目录（根本身）
C:\Program Files (x86)\
C:\ProgramData\        （仅根本身；子目录另有判断）
C:\Users\              （仅根本身）
C:\Users\<用户>\        用户主目录本身
C:\$Recycle.Bin        回收站
C:\System Volume Information
C:\Recovery
\WindowsApps            应用商店应用
\AppData\Local\Packages UWP 应用数据
\AppData\Local\Microsoft\Windows
```

### 软禁区（需 `-Force` + `-ForceReason "理由"`）

`C:\Program Files\*` 与 `C:\Program Files (x86)\*` 的子目录。

**图形界面有意不提供这个入口** —— 这类程序常依赖注册表绝对路径、
Windows 服务、更新机制，迁移后可能损坏。更稳的做法是用程序自己的设置改缓存位置。

### 云同步占位符

`OneDrive` 这类目录的重解析标记是 **云文件占位符**（`0x9000701a`），
不是链接。工具会判为 `BLOCK` 而不是「已迁」——它既没被迁移，也不该被当作已处理。

## 五、AI 标注的权限边界

**AI 只有否决权，没有批准权。**

用激进程度阶梯做**机械约束**，不靠提示词自觉：

```
keep(0) < review(1) < migrate(2) < delete(3)
```

```powershell
$aiRank = $script:Rank[([string]$ai.suggestion).ToLower()]
if ($null -ne $aiRank -and $aiRank -lt $ruleRank) {
    $verdict = 'REVIEW'   # AI 更保守 -> 行使否决
    $veto    = $true
}
# AI 更激进 -> 直接忽略，suggestion 只作展示
```

### 三条硬边界

| 边界 | 实现 |
|---|---|
| `BLOCK` / `ALREADY` **绝不发给 AI** | `$script:Sendable = @('REVIEW','MIGRATE','DELETE')` |
| AI 无权把任何判定**升级** | 只有 `AI等级 < 规则等级` 才生效 |
| AI 挂掉不影响流程 | 重试 1 次；仍失败则记 `AiStatus=failed`，保留原判定 |

### 隐私

发给 API 的是**脱敏元数据**：路径（用户名替换为 `__USER__`）、体积、文件数、
扩展名分布、是否被占用。**绝不含任何文件内容。**

- `-NoAnonymize` 可关闭脱敏
- `-Offline` 可完全离线
- 本地缓存按 `路径+体积+判定` 做 SHA256，重复运行不重复计费

## 六、清理功能的四层闸门

| 层 | 作用 |
|---|---|
| **① 判定过滤** | 只有 `FinalVerdict = DELETE` 的项可清理。AI 否决过的（降级为 `REVIEW`）**不算** |
| **② 强制预览** | 弹确认框完整列出路径与体积，勾「我已确认」后才可执行 |
| **③ 执行器独立再过滤** | `Clean-CDriveItems.ps1` **不信任界面传来的内容**，自己再挡一遍 |
| **④ 硬禁区 + 链接安全** | 见下 |

### 清理的硬禁区

```
驱动器根目录
C:\Windows\            及其子树
C:\Program Files\      及其子树
C:\Program Files (x86)\及其子树
C:\ProgramData\        （仅本身）
C:\Users\              （仅本身）
C:\Users\<用户>\        （仅本身）
C:\$Recycle.Bin
C:\System Volume Information
C:\Recovery
C:\PerfLogs
```

> 注意：`C:\Users` 只拦**它自己**，不拦子树——
> 否则 `C:\Users\<你>\AppData\Local\pip` 这类本该可清理的缓存就全被封死了。

### 两种模式

| 模式 | 说明 |
|---|---|
| **移入回收站**（默认） | 可恢复。用 `Microsoft.VisualBasic.FileIO.FileSystem` 的 `SendToRecycleBin` |
| **永久删除** | 不可恢复，需主动切换单选按钮 |

> 移入回收站**不会立即释放磁盘空间**，需要再清空回收站。

### 链接安全

遇到 Junction 时**只删链接本身**：

```powershell
$out = cmd.exe /c "rmdir `"$Path`"" 2>&1
```

用 `Remove-Item -Recurse` 会顺着链接删掉目标盘的真实数据。这一条有专门的验收断言（T15f/T15g）。

## 七、其他实现层面的安全细节

| 细节 | 原因 |
|---|---|
| robocopy 退出码 `0–7` 全算成功 | 它是**位标志**，`1` = 成功复制了文件。判 `-ne 0` 会 100% 误报 |
| 退出码为负也算失败 | 进程被强杀时返回 `-1`，只判 `>= 8` 会把它当成成功 |
| 所有路径操作用 `-LiteralPath` | 防止路径含 `[` `]` `*` 时被当通配符 |
| 不用 `Invoke-Expression` | 避免注入 |
| 所有 `.ps1`/`.psm1` 存为 UTF-8 **with BOM** | PowerShell 5.1 会按 ANSI 读无 BOM 文件，中文直接语法报错 |
| 响应体自行按 UTF-8 解码 | `Invoke-RestMethod` 在服务端不带 `charset` 时按 ISO-8859-1 解码，中文变乱码 |
| manifest 持久化在 `report/migration/` | 关掉界面后仍能回滚 |
| 全局异常安全网 | 界面任何未处理异常都拦成友好提示，不让 .NET 调试框弹出 |
